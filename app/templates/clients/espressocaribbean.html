What you're receiving

A self-contained Next.js 15 (App Router) section for Espresso Caribbean, a coffee roaster and espresso equipment supplier serving the West Indies:

  • / homepage:
    • a scroll-driven sea-chart map journey (MapLibre + GSAP)
    • services, coffee menu and equipment packages
    • After Dark (coffee mixers for bars and nightclubs)
    • mission and photo mosaic
    • a recipe QR strip and contact
  • /recipes: index of 4 recipes, each with its QR code.
  • /recipes/[slug]: 4 blank recipe templates (recipe-01..recipe-04), statically generated with generateStaticParams.

Every page is static. There's no server code, database, API or secrets.

Requirements

  • Node 20+ (built on Node 24), npm.
  • Runtime dependencies:
    • next 15.5.27
    • react / react-dom 19.1.0
    • maplibre-gl ^6.11.2
    • gsap ^3.15.0
    • clsx
  • Development dependencies:
    • Tailwind CSS 4 (@tailwindcss/postcss) and TypeScript 5
    • ESLint 9 with eslint-config-next and jsx-a11y
    • QR tooling: qrcode, jsqr, @types/qrcode (sharp comes with Next)
  • Outbound network:
    • map tiles from tiles.openfreemap.org (free, no key)
    • placeholder photos from images.unsplash.com
    • Google Fonts through next/font, which is self-hosted at build time

Run it standalone first

cd 04-development/src
npm install        # postinstall copies MapLibre worker files into public/
npm run dev        # http://localhost:3000 (add -- --port 3010 to match the original setup)
npm run build      # production build
npx tsc --noEmit && npx eslint .   # both clean at handover

Current layout (as of 2026-10-20)

  • Map: light parchment sea chart, made by recoloring OpenFreeMap Positron through CHART in MapCanvas.tsx. A dark variant was tried and rejected. Gold routes run from 9 origin countries to Atlanta, GA.
  • Journey stops:
    1. Hero: the Caribbean basin
    2. Origins: the Americas to East Africa
    3. Roastery: Atlanta at zoom 6
    4. Islands: the Lesser Antilles arc
  • Hero (desktop): a framed espresso panel with a teal left edge. Width is 64% of the screen at md, 52% at lg and 47% at xl. The map shows on the right.
  • Story cards (desktop): cards float on the left at 47% width. The photo is 37.5% of the screen height, there's space between cards, and the camera frames the real place on the right.
  • Phones: the map is a globe and cards sit at the bottom, leaving about 40% of the screen as map.
  • After Dark: night palette (--night), a three-photo collage (neon lounge, cocktail, bar counter), and empty slots for the client's copy.

Integration options (pick one)

A. Subdomain (simplest, no code changes)

Deploy the app as-is on its own subdomain (for example coffee.example.com) and link to it from the host site. For static hosting:

  • set output: "export" and images: { unoptimized: true, remotePatterns: [...] } in next.config.ts
  • run npm run build
  • upload out/

B. Sub-path of the host site (e.g. example.com/espresso-caribbean)

  1. In next.config.ts, add basePath: "/espresso-caribbean". For static hosting, also add output: "export" and images.unoptimized: true.
  2. Fix the three absolute paths that basePath does not rewrite, because they are plain strings rather than next/link:
    • Nav links: the nav hrefs in lib/content/siteContent.ts ("/#journey", "/recipes", ...) are rendered as plain <a> in SiteHeader.tsx and SiteFooter.tsx. Prefix them with the base path, or switch those anchors to next/link.
    • QR images: qrSrc() in lib/content/recipes.ts returns /qr/.... Prefix it with the base path.
    • Map worker: config.WORKER_URL = "/maplibre-gl-worker.mjs" in components/map/MapCanvas.tsx. Prefix it, or the map never paints.

    Links built with next/link already get the prefix: QrCard links, the header logo and recipe "back" links. In-page #hash links are unaffected.

  3. Regenerate the QR codes with the real public URL, including the sub-path: QR_BASE_URL=https://example.com/espresso-caribbean npm run qr. The script appends /recipes/<slug>.
  4. Serve it:
    • Static host: serve out/ under that path.
    • Host is also Next.js: use multi-zones, meaning a rewrite from the host to this app.
    • Otherwise: use a reverse proxy rule.

C. Merge into an existing Next.js App Router codebase

Only if the host already uses Next 15, React 19 and Tailwind 4.

  1. Copy components/, lib/ and scripts/ into the host. Move the routes under a segment, for example app/espresso-caribbean/page.tsx and app/espresso-caribbean/recipes/..., then update the hrefs from option B, step 2.
  2. Turn app/layout.tsx into a nested layout for that segment, without <html>/<body>. Keep the font variables on a wrapper <div>.
  3. Scope the CSS. globals.css sets :root tokens, html { scroll-behavior }, and body background, color and font, which will clash with the host. Move the tokens and base styles onto a wrapper class (for example .ec-root), keep the @theme inline block, and import the file only from the segment layout.
  4. Merge the dependencies and the postinstall / qr scripts. Copy public/qr/ and the two public/maplibre-gl-*.mjs files. Add the Unsplash remotePatterns.
  5. Keep the @/* alias pointing to wherever these files live, or rewrite the imports.

D. Non-React host (WordPress, PHP, etc.)

Use option A or the static out/ from option B, served under a path or subdomain. An <iframe> also works but is not recommended: the sticky scroll map and in-page anchors behave poorly inside iframes.

Things that must not break

  • Every map step with bounds also needs a mobile center/zoom camera. Phones render a globe, and fitBounds does nothing on the globe in MapLibre 6.
  • Keep absolutePadding: true in fitBounds. Padded flyTo calls leave padding on the map, and without this setting it gets counted twice.
  • The map only paints in a visible tab (requestAnimationFrame). A blank map in a background or hidden preview is expected behaviour, not a bug.
  • Copy rules (client requirement): every claim traces to the client's own site or to facts the client confirmed. No invented stats, locations or testimonials. No em dashes or curly quotes. The map's routes end at Atlanta, GA (DESTINATION in components/map/mapConfig.ts), which the developer chose. It still needs client confirmation.
  • Print the day QR versions. The night versions only scan on phones that can read inverted codes.
