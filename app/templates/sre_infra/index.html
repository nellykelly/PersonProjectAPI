SRE Infra Layer

The Redis-backed queueing, caching, and rate-limiting infrastructure underneath Pipeline World -- written up here on its own because it demonstrates a distinct skill set (async processing, cache invalidation, abuse protection under load) worth speaking to separately from Pipeline World's application-engineering pitch.

Queue

Every character-join event is enqueued (RQ + Redis) rather than processed synchronously in the request/response cycle -- the HTTP request returns immediately ("your character is joining"), while a worker runs the actual validate/test/build/deploy pipeline in the background. This is the standard answer to "why doesn't synchronous processing scale for anything resource-intensive or bursty": a slow or spiky workload can queue up without blocking web requests or timing visitors out.

Cache

The live world state (which characters are currently spawned, and where) is cached in Redis using the cache-aside pattern: a read tries the cache first, and only queries the database on a miss, repopulating the cache afterward. The cache is explicitly invalidated the moment a character clears the Deploy stage, rather than left to expire on a timer -- so newly-live characters show up immediately rather than waiting out a stale TTL.

Rate Limiting
